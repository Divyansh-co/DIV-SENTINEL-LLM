# SentinelPrompt

Security middleware that sits in front of an LLM and checks incoming input for prompt injection / jailbreak attempts before it ever reaches the model.

(also yes, the dashboard is called "Obsidian Ember" for no deep reason, I just liked how it sounded at 1am)

## The problem this solves

Once you put an LLM into an actual product — a chatbot, an agent that browses the web, something that reads uploaded documents or scraped content — you open the door to prompt injection. It's currently #1 on OWASP's Top 10 for LLM applications for a reason: if untrusted text (a webpage, a PDF, a support ticket, whatever) gets concatenated into your system prompt, an attacker can hijack the model's instructions from inside that "data."

Some of the specific patterns SentinelPrompt is built to catch:

- Classic jailbreaks like DAN-style prompts and "Developer Mode" style role-play attempts
- Delimiter breakout (trying to escape out of the intended prompt structure)
- Unicode homoglyph tricks (swapping in look-alike characters to sneak past keyword filters)
- Base64 / encoded payloads used to hide the actual instruction
- Indirect injection, where the malicious instruction is hidden in content the model is asked to process rather than typed directly by the user

## How it works

It's middleware, not a wrapper around a specific model. A request comes in, SentinelPrompt analyzes it against a set of detection rules/heuristics, scores it, and either lets it through or blocks it before it hits your LLM call. There's a dashboard on top to see what's been flagged over time.

## API

- `POST /api/v1/analyze` — run a piece of input through the detection engine
- `GET /api/v1/history` — past analysis results
- `GET /api/v1/stats` — aggregate stats (detection rate, latency, etc.)
- `GET /api/v1/rules` — list current detection rules
- `PATCH /api/v1/rules/{rule_id}` — tweak/toggle a rule

Auth is via API key. Swagger docs are auto-generated by FastAPI so you can poke at the endpoints directly once it's running (honestly the best way to explore this thing, better than reading my explanations here).

## Stack

- Backend: Python 3.11+, FastAPI
- Frontend: React, styled as a dark "Obsidian Ember" dashboard
- Dockerized (docker-compose) so backend + frontend spin up together

## Running it

```bash
git clone https://github.com/Divyansh-co/DIV-SENTINEL-LLM.git
cd DIV-SENTINEL-LLM
docker-compose up --build
```

The API will be up with docs at `/docs`, and the dashboard is served separately — check `dashboard.html` / the frontend service for the exact port.

## Where the numbers came from

The 100% detection / ~6.7ms latency figures in the badges are from testing against my own attack payload set (the jailbreak/injection patterns listed above) — not an independently audited benchmark, just my own test harness. Worth being upfront about that if it comes up. Take the "100%" with a grain of salt, it means 100% on the tests I wrote, not 100% against everything a determined attacker could come up with.

## What I'd still improve

- Detection rules are currently pattern/heuristic based — no ML-based classifier yet, which would probably generalize better to novel attacks
- Rule tuning UI in the dashboard is pretty basic right now
- Would like to add support for streaming responses instead of just single-shot analyze calls
- More real-world adversarial testing beyond my own payload set would make the numbers actually mean something

## Why I built it

Wanted to go deeper than "call an LLM API" and actually build a piece of security infrastructure — something closer to what an AI security engineering role would involve day to day.
